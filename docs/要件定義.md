## 2. プロジェクト概要

**システム名：** 書類・プリント管理アプリ（仮）

**システムの目的：**
家庭や学校で届く書類（プリント）を、スマホで撮影するだけでOpenAIのマルチモーダル能力を活用して自動で「種類・期限」を解釈し、アプリ内カレンダーへ自動登録・通知を行うシステム。

**関係者：**
- 講師：エンジニアスクール講師
- 開発チーム：4人（期間：4週間 / 公開前提）

## 4. 業務フロー（As-Is / To-Be）

### 現在の業務（As-Is）

1. 書類が届くが、後回しにして積み重なる。
2. 処理する際、「いつまでか？」を人間が毎回読み解く（高い解釈コスト）。
3. 各自の手帳やカレンダーアプリに手動で書き写す、または家族に口頭やLINEで連絡する（共有漏れや期限忘れが発生）。

### 新システムでの業務フロー（To-Be）

1. ユーザーはメールアドレスを必須として新規登録（UI-001）を行う。この際、1人利用時にも即座にシステムを利用できるよう「個人グループ」が自動生成される（リマインド日数はデフォルトで「3日前」に設定される）。追加で他メンバーを招待して共同利用することも可能。
2. グループ内は「メンバー全員が同等の権限」を持ち、誰もが書類の登録・編集・削除を行うことができる。ただし、誤操作によるグループ全体の消失を防ぐため、「グループの削除」のみ作成者（`created_by`）に制限される。
3. 書類が届いた瞬間、ユーザーはスマホで「写真を撮るだけ」。
4. バックエンドでOpenAI APIが自動で書類の意味（期限・種類）を解釈。
   > ※AI解析に失敗した場合は、プレースホルダーや空欄の状態で編集画面を表示し、手入力を促すUXとする。
5. 解析確認画面にて、AIの抽出結果をユーザーがその場で必要に応じて修正・編集した上で、登録ボタンを押す。
6. 登録完了後、所属するグループのカレンダーへ即時自動反映される。
7. 同時に、グループ内の他メンバーのアプリ内ヘッダーにある「🔔（ベルマーク）」にお知らせ（「〇〇さんが書類を登録しました」）が即時表示される。
   > ※書類を登録した本人の画面にはこの通知は表示されない。
8. 登録された書類のタスク（提出や支払いなど）が完了したら、ユーザーは詳細画面から「済スタンプ」を付与でき、カレンダー上でも一目で完了状態がわかるようになる。このとき、まだ送信されていない未来のメールリマインドタスクは自動的にキャンセルされる。
9. ユーザーが設定画面で指定した日数（デフォルト3日前）になり、かつタスクが完了（済）になっていない場合、登録されているメールアドレス宛に「リマインドメール」が自動送信される。

## 5. 機能要件

| ID | 機能名 | 概要 | 詳細仕様 |
|----|--------|------|----------|
| FR-001 | ログイン/新規登録 | ユーザーの認証処理 | 新規登録時はメールアドレスの登録を必須とする。認証基盤はFirebase Auth。初期設定としてリマインド日数を「3」で保持する。新規登録完了時に「個人グループ（例: 〇〇さんのマイグループ）」をバックエンド側で1つ自動生成する。 |
| FR-002 | グループ作成・招待 | 共有のためのグループ管理 | ユーザーは任意の共有グループを新規作成し、他の登録者を招待できる。招待時は `invitations` テーブルにレコードを発行。グループ内メンバーは全員同等権限（書類登録・編集・削除可能）とし、role等による権限分離は行わない。グループ自体の削除操作のみ `created_by` のユーザーに制限する。 |
| FR-003 | 写真スキャン・AI解析 | 撮影画像からの情報抽出 | OpenAI API（GPT-4o等）のStructured Outputsを活用して「期限（有無含む）・種類（タイトル）・カテゴリ」を自動抽出する。※「宛先」フィールドは解析対象外とする。 |
| FR-004 | 解析確認・手入力UX | 柔軟な登録処理 | AIの解析結果を確認画面（UI-004）に表示し、直接編集して登録できる。AI解析が失敗した場合は、各フィールドを空欄表示とし、ユーザーがスムーズに手入力へ移行できるUXを担保する。 |
| FR-005 | アプリ内カレンダー表示 | 登録スケジュールの同期 | FullCalendarを利用した月表示対応UI。所属グループのスケジュールが全員に同期される。「済スタンプ」が付いている書類は、カレンダー上でグレーアウト等の視覚表現を行う。 |
| FR-006 | 編集・済スタンプ機能 | 登録データの事後修正・完了管理 | 登録完了後も詳細画面（UI-005）から各項目を再修正できる。書類ごとに「済スタンプ」をON/OFFできる切り替えスイッチを配置する。済スタンプがONになった場合、バックエンドは `notification_schedules` にある当該書類の未送信リマインド（`status='pending'`）を即座に `'cancelled'` へ更新する。 |
| FR-007 | 期限なし書類管理 | カレンダー外の書類保管 | 期限が設定されていない書類（`has_deadline = false`）を、カテゴリ別に保管・検索・一覧表示できる。 |
| FR-008 | グループ単位共有 | グループ内でのデータ共有 | 書類はすべて所属グループ単位で一括共有。1人利用時も、新規登録時に自動生成された個人グループに紐づく形で全く同じシステムロジックが動作する。 |
| FR-009 | アプリ内お知らせ＆可変メールリマインド | 通知・リマインドの制御 | ①書類登録時：ヘッダーの「🔔」に「〇〇さんが書類を登録しました」と表示。登録した本人の🔔には表示しない。お知らせはユーザーが個別タップした時に既読に更新される。②期限前リマインド：ユーザーごとに設定されたリマインド日数に基づき、期限のN日前に登録メールアドレスへリマインドメールを自動送信する。 |
| FR-010 | カテゴリ管理機能 | カテゴリのマスター化と紐づけ | 書類の種類を分類するマスタとして `categories` テーブルを使用。初期データとして「学校・医療・行政・保険・その他」の5カテゴリをシーディングする。グループごとにカテゴリを追加・編集でき、書類（`documents`）に紐づける。 |
| FR-011 | 課金・制限管理 | 月間制限と1日自動リセット | 月間の無料スキャン枚数上限を超えた場合、Stripe決済導線を表示する。累積スキャン枚数のリセットは、Celery Beatによる定期タスクとして毎月1日AM0:00（JST）に実行される。 |

## 6. 非機能要件

| 項目 | 内容 |
|------|------|
| パフォーマンス | 通常画面の遷移は2秒以内。OpenAIによる解析処理中は「解析中」のローディングアニメーションを表示する。 |
| 可用性 | 成果発表会（デモ本番）および審査期間中に、サーバーおよびOpenAI連携が安定して動作していること。 |
| セキュリティ・画像配信 | 認証を通していない第三者が他人の書類データにアクセスできない制御を行う。アップロードされた画像はCloudinaryの「署名付きURL（Signed URLs）」を発行して一時的なアクセス権を付与する。 |
| 外部API・リマインドリトライ設計 | OpenAI APIやSendGrid等の外部通信が失敗した場合、バックエンド側で「指数バックオフによる自動リトライ（最大3回）」を実行する。リマインド送信処理の成否やリトライ回数は `notification_schedules` テーブルのステータスおよびカウンターに記録・同期する。 |
| 通知スケジュール管理 | ユーザー設定の「N日前」に確実にリマインドメールを送信するため、Celery Worker + Redisを用いたバックグラウンドスケジュールタスクを安定稼働させる。 |

- 開発環境と本番環境でログ出力レベルを出し分ける（MUST要件）。
- 開発用ツール（Adminer・Redis Commander）は本番デプロイ時に除外する。

## 11. リスクと対応方針

| リスク | 対応方針 |
|--------|----------|
| リスク1：OpenAIやメール送信等の外部API通信失敗・遅延 | 指数バックオフによる自動リトライ（最大3回）をCelery Worker側で実行する。リトライのたびに `notification_schedules.retry_count` をインクリメントし、3回失敗した時点で `status='failed'` に確定させエラーログに記録する。 |
| リスク2：AI解析失敗時のUX | 確認画面（UI-004）にて「解析ができませんでした。手動での入力をお願いします」等のアナウンスと共に各フィールドを空欄で表示する。ユーザーがストレスなくその場で手動登録へ移行できるUXとする。 |
| リスク3：BE②担当範囲の過負荷 | LLM連携・Stripeの基本実装をWeek2で優先し、Celery通知はWeek3に着手する週次優先度をチームで合意する。 |

## 付録：OpenAI Structured Outputs スキーマ定義

FR-003で使用するLLMレスポンスのJSONスキーマ（BE②とFEのインターフェース合意用）

| フィールド名 | 型 | NULL可 | 説明 |
|-------------|-----|--------|------|
| `title` | string | No | 書類のタイトル（例：「遠足のお知らせ」） |
| `category` | string | Yes | カテゴリ名（例：「学校」「医療」）。不明な場合はnull。 |
| `deadline` | string (ISO8601) | Yes | 期限日（例：「2026-07-01」）。期限なし・読み取り不能の場合はnull。 |
